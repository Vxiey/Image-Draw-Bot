## Reproducible measurements

Run `../security-venv/bin/python benchmark_v148_ui_calibration.py` from the repository. Raw alternating samples, source hashes, platform and result digest are in `docs/v148-batch06-ui-calibration-benchmarks.json`.

The benchmark compiles the real before/after `_apply_ui_state` bodies and runs 1,000 progress-state updates through deterministic variable/widget adapters. Display assignments cross the Python/Tcl boundary with real `Tcl.setvar`; controller readiness methods are counted adapters. It measures state construction and presentation dispatch, **not** CustomTkinter raster painting, full-window frame rate, deferred responsive-layout jobs, physical input or GPU speed. Every sample must have the same final visible-state, wizard, controller-state and readiness-count digest.

| --- | ---: | ---: |
| Median renderer workload | 75.770 ms | 39.163 ms |
| Presentation configure calls | 38,000 | 38 |
| Presentation Tcl property writes | 55,000 | 55 |
| Controller Start updates | 1,000 | 1,000 |
| Each of five readiness reads | 1,000 | 1,000 |
| Final-state SHA-256 | `26983f661b269e210c340c09211adb506c26d304928221fd98e0cb59b13efd02` | Same |

This workload is about **1.93× faster**. Only UC04 is a measured dispatch optimization; the layout groups are usability/correctness changes and carry no unmeasured speed claim.

Resetting an incompatible saved frame is part of the existing manual calibration recovery contract, not an additional group beyond UC03's explicit draft editing UI.

- Root owns selected-view PNG export and its label/tooltip change. It is not counted here.
- The batch05 Windows guide teardown assertion now ignores empty Tcl separator lines while preserving exact nonempty scripts, owned-command deletion, unrelated-command liveness and functional unrelated MouseWheel dispatch. This is a verification correction, not a new product improvement.

## Validation status and limits

The code has no antivirus-evasion logic, signing change, network download or native input change. CPU/Tk tests do not establish physical GPU performance or antivirus clearance. New native layout tests must pass on Windows CI before a release claim. Product/test changes are frozen for the shared full-program gate; only a concrete review finding and the parent coordinator's permission should reopen them. `git diff --check` passes.

A read-only post-freeze reproduction found one minor UC11 follow-up: native focus under a CTkScrollableFrame's separate outer `_parent_frame` (such as its scrollbar) is not currently recognized as that panel by `_focused_panel`. Ordinary body-control focus is covered. A narrow transition can therefore choose the previously selected compact page in that case. The coordinator has recorded this for completion of UC11 with a focused regression at a subsequent source checkpoint; it is not an additional improvement count or a native input permission issue.
