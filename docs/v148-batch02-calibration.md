# v1.0.148 calibration/browser/Paint improvements — batch 02

This ledger records **69 grouped behavior improvements** against checkpoint
`1c09774ad22088c5c30a8f8220b6b451fdee9659`. Tests, documentation, formatting and
multiple invalid examples of the same defect are not counted separately. This
is an implementation batch, not a claim that the 1,000-improvement target or
release publication is complete.

The numbered groups include conservative rejection of invalid calibration data,
more accurate visual evidence, bounded/cancellable read-only analysis and
measured CPU optimizations. No flagged release binary was downloaded or run. No
mouse/keyboard input was generated by the local regression tests.

## Shared integration excluded from this count

- The GetColorPositions/PaintToolCalibration anchor-before-HWND-commit fix completes batch01 UI37, which made the same correction in AppToolCalibration. Its code and regressions remain here, but it is not counted as a new behavior.

- Root RT19/RT20 own the end-to-end 100% opacity application and honest unknown/dry-run status. This module supplies a target at 100% only when a slider is verified and supplies explicit unverified-state metadata; those planner changes are not separate entries here.
- Root RT21 owns fresh brush selected-state verification, its highlight scoring and the conservative runtime guard. `verify_brush_selection(plan_dict, target_index)` performs one fresh read-only capture and checks a unique bright/chromatic rim against both background and control center. Generic icon/background contrast is not selected-state evidence. Unknown themes/markers return false. The helper, conservative guard and initial/adaptive runtime integration are not separate entries here.
- Root RT12 owns shared image-buffer cleanup. This batch also closes owned retry recaptures, calibration capture/conversion buffers and replaced palette snapshots; its tests preserve caller-owned image lifetime. These cleanup call sites are not counted again. Shared capture budgets/dimension handling support root RT11/RT13. CAL24 counts the distinct algorithmic retention change from all candidate screenshots to only the current winner.
- RuntimePaths owns the general staged file-set implementation. CAL40 counts the actual paired Paint calibration behavior only. It provides rollback after a publication exception, not filesystem-wide crash atomicity. Failed rollback can retain recovery backups as reported by the shared helper.
- TargetProbe/TargetCapture owner-root metadata supports CAL13 and is counted only there. The root native helper's tests verify its own handle/process boundary.
- A proposed optimization of the legacy `patch_change_score` helper was removed after integration showed the active runtime no longer calls it. It contributes no improvement count or runtime performance claim.

## Validation

- **109 new focused tests:** 107 passed on Linux; 2 Windows PowerShell tests are skipped locally. The Windows tests parse the complete focus-checked UIA script without executing it against Paint, and execute only generic list→JSON serialization. Existing Windows script-transport tests remain in place. The final focused suite was also rerun independently after review corrections.
- **315 related unittest tests:** 306 passed; 9 Windows-only checks skipped. The run includes the 106 then-current new tests and existing Paint, browser, high-DPI, anchor, palette, recovery, profile-isolation and drawing-control regressions.
- Independent review caught and corrected three gaps before the final focused run: unknown cache fields could violate the reader item budget; a resized saved exact-color layout could prevent any new first Open capture; and RGB PNG transparency keys bypassed visible-marker composition. The cache writer now uses a schema whitelist, a valid explicit opener can start a fresh incompatible frame while preserving compatible translations, and keyed RGB images use visible composition. These corrections remain within CAL14, CAL13 and CAL61 respectively, with no extra count. The earlier 315-test run preceded these final corrections.
- Four pre-existing layout-fingerprint function tests were called explicitly with isolated temporary directories because this environment has no pytest installed; all four passed.
- No physical Windows UI, GPU or real drawing latency is claimed by these Linux results. Exact source/frozen Windows CI remains the release gate owned by root.

## CPU measurements

The opt-in benchmark compares the checkpoint source with the current functions,
using the same deterministic repository/generated images. It checks complete
output equality first (float tolerance 1e-9), warms both paths and reports the
median of seven runs. Palette dependencies of the baseline browser/Paint modules
are also loaded from the checkpoint. Timings describe these fixtures on this
Linux CPU host; they do not predict native capture or whole-drawing speed.

The palette fast path is checked against the independent four-connected pixel
walk on 25 generated overlapping-rectangle cases, including merge order. The
noisy-image shortcut only rejects when the required exact 5×5 swatch interior
cannot exist; a separate regression retains a valid swatch in the same noise.

markers and blank images. The unused-ROI fixture records zero full-ROI crops
instead of the prior one; a 5000×1120 RGB region is 16,800,000 raw pixel bytes,
without claiming a measured process-RSS difference. Reference-template tests
record one asset load across repeated requests and enforce immutable arrays.
