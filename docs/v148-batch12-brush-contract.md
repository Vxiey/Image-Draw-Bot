## Reproduced public behavior

The real `DrawBotApp.options` accepts **Other drawing app**, a fixed **4 px**
brush, **Auto**, **High likeness**, **Standard** planning resolution and a
**Custom 60-second** budget. A deterministic texture is generated by the existing
`texture_image` fixture and resized to 48×32, then passed through the unmodified
public `make_plan` entry for a 96×64 canvas.

Actual acceptance of the initial plan is `BELOW_QUALITY_GATE`, with a 12.833 s
projected draw time, 53 s usable budget and 40.167 s headroom. The real tuner
therefore proposes `quality-rescue-pixel-accurate`. Neither acceptance nor the
rescue decision is replaced by a fixture. Before this correction, that proposal
changed the 4 px brush to 1 px. Without verified size controls, AdaptiveBrush
correctly fell back to its supplied default, but that default was now false:
all 212 planned entries used 1 px.

The actual executor had no control with which to change the user's fixed 4 px
brush. A native-boundary fake rasterized its sent moves, presses and clicks with
that unchanged physical width. A second raster applied the plan's declared width
to the same input coordinates and colors. **1,962 pixels differed**. This
comparison isolates the width mismatch; it does not compare resized preview
images or claim measurement of a real application's ink.

The same public UI → planner → executor reproduction found the other forced
width in `AutoDrawing`: both **Masterpiece** and **Auto + Unlimited** on a sparse
line-art source selected Pixel Accurate and silently replaced the declared
4 px width with 1 px. Their physical-versus-declared raster comparisons each
differed at **547 pixels**. The baseline regression ran two test methods with
three failing cases before either policy source file changed.

## Narrow correction

- `EndToEndAutoTuner.propose_rescue_options` still selects the same Pixel
  renderer, resolution, quality and bounded rescue policy, but preserves the
  declared or preflight-resolved `brush_px`.
- `AutoDrawing.resolve_drawing` still selects Pixel Accurate for Masterpiece
  and the applicable Unlimited route, while preserving that same width.

No planner, simulator, adaptive brush selector, CanvasGuard, mouse input,
calibration or brush-selection verification is changed. A replacement still
has at most one rescue attempt and is scored by the ordinary acceptance code.
Preserving a wide brush does not promise that the requested fine detail is
physically drawable or that the final quality gate passes.

With no verified controls, the fixed width is now the model used for both
planning and the executor's unchanged physical brush. Native CanvasGuard can
still skip paths outside its inset; the test accounts for both sent and skipped
paths rather than weakening clipping to make every path execute.

## Verified-control comparison

The control case uses actual Gartic UI options and the actual
`plan_browser_brush_size` detector on a synthetic screenshot. Four visible
controls independently establish physical widths **2, 4, 8 and 16 px**. A fifth
nominal control is blank and remains unverified. Public Gartic level 2 resolves
to physical 4 px, as in the real Start preflight.

The actual Masterpiece → Pixel route retains that preflight width, then the
existing AdaptiveBrush engine assigns only widths from the verified set.
`execute_plan` performs the real control-selection flow; the fake changes its
physical brush only when the corresponding control is clicked, and the
selected-state boundary checks the resulting physical width. No 1 px entry or
control is invented. The same fixed and verified cases keep the existing button
release and brush-specific CanvasGuard behavior.

An exploratory Auto case with verified controls selected the ordinary
`quality-rescue`, because its modeled control costs consumed more of the
available budget. That valid result was not overwritten to force a Pixel-rescue
test. The fixed-width Auto regression exercises the actual Pixel-rescue branch;
the verified Masterpiece case exercises the other corrected policy and the
shared physical-selection contract.
